# ADR 0001: Stack and tooling for the first commit

- Status: accepted
- Date: 2026-11-12

## Context

The design documents in `docs/` settle the product stack (Next.js 16, Drizzle on Neon, Better Auth, Tailwind v4, Stripe, Vercel). Two details were left to the first build session: which package manager to use, and which Node version to pin. The architecture document said pnpm; the project scaffold conventions use npm. This ADR records the choice so the two are never mixed.

## Decision

- **npm** is the package manager. `package-lock.json` is committed and CI installs with `npm ci`.
- **Node 24 LTS**, pinned in `.nvmrc` and `engines`. Vitest 5 requires Node 22.12 or newer, and 24 is the current long-term support line that Vercel also runs.
- **Next.js 16.4** generated by `create-next-app` with Cache Components on, the App Router, `src/` and the `@/*` alias.
- **TypeScript** with `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride` and `noImplicitReturns`.
- **ESLint** (flat config) with Next's rules, the full `jsx-a11y` recommended set as errors, and a `no-restricted-imports` rule that keeps `src/domain/` free of framework and I/O imports. **Prettier** formats code; the design docs stay hand-formatted.
- **Vitest 5** with v8 coverage, measured on `src/domain/`.

## Alternatives considered

- **pnpm:** faster installs and stricter dependency resolution. For a single-app repository with no workspaces the difference is small, and npm needs no extra setup on CI, Vercel or a reviewer's machine. Revisit if the repository becomes a monorepo.
- **eslint-plugin-boundaries for the domain rule:** more expressive, but ESLint's built-in `no-restricted-imports` covers the one rule this project needs without another dependency.
- **Node 22:** still supported, but the local 22.1 install is below Vitest's floor, so upgrading to the newer LTS cost the same as patching 22.

## Consequences

- Every command in the docs and README is an `npm run` script.
- Contributors need Node 24 (`nvm use` reads `.nvmrc`).
- A change of package manager later means regenerating the lockfile and updating CI, Vercel and the docs together.
