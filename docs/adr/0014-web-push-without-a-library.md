# ADR 0014: Web push written against the standards, without a library

- Status: accepted
- Date: 2026-11-12

## Context

Players can now get rain-outs, sub requests and score confirmations as phone notifications (issue #176). The installable app already has a service worker, and the outbox already delivers every notice with retries. What was missing is the server side of the Web Push protocol: encrypting each message for one device and proving to the push service who is sending it.

[architecture.md](../architecture.md), section 14, planned to use the `web-push` package. Three options:

1. **`web-push` 3.6.7.** The long-standing package, last released in January 2024. It sends with Node's `https` module and its own retry rules, so tests would need to intercept HTTPS or call its lower-level request builder. It brings four dependencies (`jws`, `asn1.js`, `http_ece`, `https-proxy-agent`).
2. **`web-push` 4.0.0.** Released six days before this decision. Too new to adopt for something that touches every notification.
3. **Write the protocol with Node's `crypto`.** Three short standards: RFC 8291 (message encryption), RFC 8188 (the `aes128gcm` encoding it uses) and RFC 8292 (VAPID). Node has every primitive: P-256 key agreement, HKDF, AES-128-GCM and ES256 signatures.

## Decision

Option 3. `src/lib/push/web-push.ts` (about 200 lines) builds the push request (encrypted body plus `Authorization`, `TTL`, `Urgency` and `Topic` headers) and sends nothing. `src/services/push.ts` posts it with `fetch` and turns the answer into sent, gone (404 or 410: delete the device) or failed (retry later).

How we know it is right:

- The encryption reproduces the worked example in RFC 8291, Appendix A, byte for byte.
- A test device (`src/lib/push/test-device.ts`) holds a real key pair and decrypts what it receives, as a browser would. Every outbox test delivers to this recorded endpoint and reads back the exact notification. No test reaches a real push service.
- The VAPID token is checked with the public key, and its claims (audience, expiry under 24 hours, subject) are asserted.

## Consequences

- No new dependency. The code is small enough to read in one sitting, and each step names the section of the standard it follows.
- We own the code. The standards have been stable since 2017, and every browser's push service speaks the same protocol, so there is little to keep up with. If a push service ever needs something these standards don't cover, `web-push` is a drop-in replacement for `src/services/push.ts` alone.
- Only the one-record `aes128gcm` encoding is supported, which caps a notification at about 3,990 bytes. League notifications are a title, two short sentences and a path, well under that.
- VAPID keys come from `VAPID_PUBLIC_KEY` and `VAPID_PRIVATE_KEY`, generated by `npm run push:keys` into `.env.local`. Without them push is off: the profile page hides its push section and the outbox suppresses push copies as `push_off`. Rotating the keys invalidates every subscription, so the script refuses to replace a key that is set.
