# Accessibility audit, November 2026

Target: WCAG 2.1 AA (the project also holds itself to the 2.2 AA rules in
[the design system](../design-system.md)). Method: a read of the code, with no
running app, for the screens added in the last few days, plus a scan of the
whole of `src` for the patterns that cause the common failures. The shared
foundations were checked first, then each screen.

Most of the new screens are still open pull requests, so a finding's
**Where** names the pull request whose code carries it. Findings in code that
is on `main` are fixed in the pull request that closes the audit issue;
findings in code still in a pull request are listed in a second issue (#500) and are
fixed once that pull request merges, so no fix collides with a branch in
flight.

## What already holds

- **Tokens and contrast.** Every text, outline and focus pair is tested in both
  themes (`src/design/tokens.test.ts`). The focus ring is 3px with a 2px
  offset on every element (`globals.css`), and no stylesheet removes an
  outline except the layout's `<main>` focus target.
- **Touch targets.** Fields and selects are at least 44px tall from the base
  styles; buttons are `btn` (44px); the checkboxes reviewed sit inside 44px labels.
- **Motion.** Press feedback and every keyframe sit behind
  `prefers-reduced-motion: no-preference`, and a global reduce rule shortens
  anything left.
- **Structure.** No click handlers on non-interactive elements, no images
  without `alt`, every table checked has real `<th scope>` headers, dialogs
  and forms use real buttons, and the new brackets are server-rendered lists
  with a plain-list alternative and a keyboard-reachable scroll region.
- **Automation.** Every new screen's end-to-end spec runs `expectNoAxeViolations`
  (WCAG 2.0, 2.1 and 2.2 AA tags), at least on its main screens.

## Findings, worst first

Severity: **High** blocks or misleads someone using a screen reader or the
keyboard on a core task; **Medium** makes a task harder; **Low** is polish or
defence in depth.

### 1. High: countdowns never announce when time is short

**Where:** daylight and field-time clock (`src/components/game-clock.tsx`,
`live/permit-watch.tsx`, #476); other groups on the fields
(`admin/today/handovers-card.tsx`, #460).

The clock is `role="timer"` with `aria-live="off"`, which is right for a line
that ticks every 15 seconds, but nothing else tells a screen reader when the
phase changes ("30 minutes left", "play must end now", "past the end of the
permit"). The ref who relies on a screen reader at dusk gets the end time once,
on arrival. The permit note is `role="alert"`, which does announce, but only
when it first appears, and it can come and go.

**Fix:** keep the ticking line silent and add a visually hidden polite status
that changes only when the phase or a threshold (30, 15, 5 minutes) is
crossed. Pair the red border with the text that already says why (the border
is never the only cue). Unit-test the announcement text at each threshold.

### 2. High: the guest-team sign-up form turns off validation and loses focus

**Where:** `src/app/l/[league]/events/[event]/guest-signup-form.tsx` and
`src/app/guest/[token]/sign-form.tsx` (#479).

- The form is `noValidate` with `required` fields and returns one message in a
  single `role="alert"` paragraph. The message is not tied to a field (no
  `aria-invalid`, no `aria-describedby`) and focus stays on the button, so
  someone using a screen reader hears that something went wrong but not which
  field. WCAG 3.3.1 and 3.3.3.
- On success the form is replaced by the confirmation, so the focused button
  disappears and focus falls to the top of the page; the confirmation holds a
  link that is shown once and can't be shown again.
- The button uses `disabled={pending}`, which drops focus; the design system
  asks for `SubmitButton` (busy, not disabled).

**Fix:** per-field errors from the action (`aria-invalid`, `aria-describedby`),
focus the first invalid field or the error summary, focus the confirmation
heading on success, and use `SubmitButton`.

### 3. Medium: errors and notices after a redirect are not reliably announced

**Where:** systemic. 274 `role="alert"` and `role="status"` elements, most of
them rendered by the server into a page that was reached by a redirect with
`?saved=` or `?error=` (the shirt order, lost and found, polls, ejection,
rulings and others). A live region that is already in the page when it loads is
not announced by most screen readers, and keyboard focus stays at the top of
the page, so a long form's error can be below the fold.

**Fix:** a small `FlashMessage` component (`src/components/flash-message.tsx`)
that renders the same message, takes focus once on mount (`tabIndex={-1}`) and
keeps its role. The shirt order uses it; the other screens adopt it as their
branches merge (#500).

### 4. Medium: the rulebook search leaves focus in the search box after a jump

**Where:** `src/components/rulebook/rulebook-search.tsx`,
`rule-highlight.tsx` (#490).

Choosing a result changes the address and scrolls the rule into view, but focus
stays on the result link, so the next Tab goes to the next result, not into the
rule, and a screen reader isn't told where it landed. WCAG 2.4.3.

**Fix:** after scrolling, give the target `tabIndex={-1}` and focus it with
`preventScroll`.

### 5. Medium: sport standings explain abbreviations only in a tooltip

**Where:** `src/app/l/[league]/seasons/[season]/standings/page.tsx` (#488):
`<abbr title="…">` for "RF", "RA" and the difference column.

The `title` is not shown on touch screens or announced reliably, so a phone
user at the field sees "KF" and "KA" with no meaning. WCAG 1.3.1 and 3.3.2.

**Fix:** put the full words in a visually hidden span inside each header, or a
legend under the table, and drop the `title`.

### 6. Medium: disclosure summaries are under 44px

**Where:** `<summary>` rows with only `cursor-pointer underline` in the captain
polls ("Who voted", "Remove…", #454), the code of conduct editor (#405) and
shared fields (#460). The shirt, daylight and interest summaries already have
`min-h-11`.

**Fix:** the same `min-h-11 content-center` the other screens use.

### 7. Medium: ejection takes one tap and has no undo

**Where:** `live/eject.tsx` (#493). Choosing a player and pressing "Eject the
player" is final: the player leaves the kicking order and a report is filed.
At the field, with a bright screen and a thumb, a wrong tap of the select is
easy. WCAG 3.3.4 does not strictly require a confirmation here (it covers legal,
financial and data changes), but the cost of a mistake is high.

**Fix:** a second step: "Eject Sam Rivera from Team A?" with a confirm and a
cancel, using the existing dialog pattern, or a checkbox-free confirm page.

### 8. Low: tables and loading states on the shirt order

**Where (main):** `admin/seasons/[season]/shirt-order/page.tsx`.

- The totals row in `<tfoot>` renders data cells as `<th>` with no `scope`, so
  a screen reader reads each count as a column header.
- The table has no caption, so the screen reader's table list shows "table".
- The loading fallback is a bare `<p>` instead of `PageLoading`.

**Fixed** in this pull request: the totals row uses data cells, the table has a
caption and the loading state is `PageLoading`.

### 9. Low: `disabled={pending}` on newer forms

**Where:** interest sign-up (#463), guest sign-up (#479), code of conduct
(#405). A disabled button drops keyboard focus while the action runs. The
design system's `SubmitButton` marks the button busy instead and keeps focus.

### 10. Low: hints inside labels lengthen the field's name

**Where:** `guest-signup-form.tsx` and a few others put the hint `<span>` inside
the `<label>`, so a screen reader reads the hint as part of the name. Move the
hint outside and point at it with `aria-describedby`.

## Automation gaps

- Every new spec runs axe on its main screens, but only `smoke` and `screens`
  turn on the dark theme, so the dark pairs of the new components (stickers,
  bracket winners, the clock's urgent border) rely on the token test alone.
- No spec scans a screen in its **error** state (a rejected form), its
  **expanded** state (the opened `<details>`) or after a **keyboard-only** path.
  The fixes above add those to the specs they touch.
- Reduced motion has no test. The stylesheet rule is global, so the risk is
  low, but a test that emulates `reducedMotion: "reduce"` on the bracket and the
  game clock would keep it that way.

## Not checked

Colors were checked against the tokens, not measured on rendered pages; team
colors on badges (not text) were not measured; screen reader output was not
run. A manual pass with VoiceOver on a phone is still worth doing before the
league's first game of the season.

## Final sweep, 16 November

A pass over `main` after the feature merges, with axe 4.14 (WCAG 2.0, 2.1 and
2.2 AA tags) in Chromium at 412 px wide, a production build and the seeded
league.

- **Public pages.** Every page in `lighthouserc.json` (38 addresses, the
  embedded schedule and widget included) was scanned in the light and the dark
  theme with reduced motion on: no violations, no sideways scroll, and
  `<html lang>` set on all of them. Both themes' contrast pairs also stay
  covered by `src/design/tokens.test.ts`.
- **Signed-in screens.** `e2e/flows/screens.spec.ts` scans screens at 375 and
  1,280 px in both themes. A route-by-route check against the specs found four
  screens nobody scanned: the player's concerns, the set-up lead's checklist,
  the not-on-my-team lists and demo mail. They are added to that spec.
- **Finding 1, in code that is on `main`.** The game clock and the permit
  watch on the live scoring screen were announced every time they ticked: the
  permit line was a polite status that changed each minute, and the warning was
  an alert whose text changed with the minutes. The visible lines are now
  silent, and one hidden status, shared by both, changes only at a phase
  change or at the 30, 15 and 5 minute marks (`src/domain/gameday/announce.ts`,
  unit-tested at each mark). When sunset ends play first (#467), the permit
  watch's sentences name the daylight instead of the permit. The same fix for the daylight clock and field handovers stays in #500,
  since that code is still in pull requests.
- **Still open.** Findings 2, 4 to 7, 9 and 10 sit in code that has not merged
  (#500). Screen reader output, rendered contrast of team colors and a
  VoiceOver pass on a phone have still not been run.
